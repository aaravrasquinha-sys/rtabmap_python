# RTAB-Map SLAM Phase 0 - Ubuntu Linux Terminal Suitability Assessment

## Executive Summary

✅ **YES, this project is suitable for running in Ubuntu Linux terminal directly**, with important caveats about hardware requirements and dependencies. The codebase is well-structured, pure Python, and designed to run entirely from the CLI.

---

## Project Overview

**Type:** Robotic SLAM (Simultaneous Localization and Mapping) Pipeline  
**Architecture:** Single-threaded Python implementation of RTAB-Map-style vision pipeline  
**Components:** Feature detection → Odometry → Memory management → Loop closure detection → Pose graph optimization → 3D mapping

---

## Project Structure

```
rtabmap_slam_phase0/
├── pyslam/                    # Main package
│   ├── core/                  # Config, logging, types, Lie algebra
│   ├── frontend/              # Feature detection & odometry
│   ├── graph/                 # Pose graph (GTSAM/native backends)
│   ├── loop/                  # Loop closure verification
│   ├── mapping/               # Point cloud assembly & export
│   ├── memory/                # Frame/keyframe storage
│   ├── sensors/               # Data sources (RealSense, bags, synthetic)
│   ├── tools/                 # Evaluation & environment probing
│   ├── vpr/                   # Visual place recognition

├── tests/                     # Gate suite & synthetic scenarios
├── run_slam.py               # Hardware (D435i camera) live capture
├── run_bag.py                # Replay recorded rosbag files
├── run_synth.py              # Pure synthetic (no hardware needed)
├── Runbook.md                # Detailed usage guide
└── Phase_Evaluation.md       # Testing checklist
```

## System Requirements

### **Minimum System Requirements:**
- **OS:** Ubuntu 18.04+ (tested environment: generic Linux)
- **Python:** 3.8+
- **Processor:** Any modern multi-core CPU (runs single-threaded by design)
- **RAM:** ≥4GB (typical runs use ~500MB-2GB, peaks depend on map size)
- **Disk:** ~2GB free space (for test runs and output artifacts)

### **No Special System Configuration Needed**
- ✅ No kernel modules required
- ✅ No CUDA/GPU support (pure CPU)
- ✅ No Docker/containers (though compatible)
- ✅ No GUI required (runs headless)

```bash
pip install numpy scipy scikit-learn opencv-contrib-python pyrealsense2
```

**Breakdown:**
| Package | Purpose | Notes |
|---------|---------|-------|

| `pyrealsense2` | Intel RealSense SDK | Only needed for live hardware; not needed for synthetic/bag replay |

### **Optional: GTSAM**

```bash
pip install gtsam
```

- **Status:** Automatically used if available; safe to omit
- **Fallback Behavior:** Pipeline gracefully falls back to native backend with a log message: `"Using native pose-graph backend."`

- **Installation Note:** May conflict with `numpy<2.0` constraints; Python 3.9+ recommended if installing

### **No Heavyweight Dependencies**
- ❌ No PyTorch, TensorFlow, or deep learning frameworks
- ❌ No CUDA/GPU compute
- ❌ No heavy visualization libraries (PLY files written as text, can be viewed with external tools)

## What Can Run Without Hardware

### ✅ **Fully Runnable on Ubuntu Terminal (No Camera/Hardware)**

#### **1. Self-test (Validation Suite)**
```bash
python3 -m pyslam.selftest
```
- **Runtime:** ~50 seconds
- **Purpose:** Validates entire pipeline via synthetic data gates
- **Expected Output:** `6/6 passed`
- **Hardware needed:** None
- **Recommended:** Always run first after extracting/cloning

#### **2. Synthetic Scenarios (Demo & Validation)**
```bash
python3 run_synth.py                        # Square-loop scenario (validated)
python3 run_synth.py --scenario corridor    # Harder scenario (known to fail loop closure)
```
- **Runtime:** ~30-60 seconds per run
- **Purpose:** End-to-end demo without any hardware or recorded data
- **Output:** Generates ground-truth trajectory, ATE metrics, 3D map (PLY format)
- **Hardware needed:** None

#### **3. Environment Probe (Diagnostics)**
```bash
python3 -m pyslam.tools.env_probe --realsense
```
- **Runtime:** ~2 seconds (with hardware detection, ~10-30s if querying camera)
- **Purpose:** Verify installed packages, check camera if connected
- **Useful for:** Troubleshooting setup issues
- **Hardware needed:** None (optional RealSense hardware)

### ⚠️ **Requires Hardware (RealSense D435i Camera)**

#### **Live Capture**
```bash
python3 run_slam.py --realsense --imu                  # Live capture
python3 run_slam.py --realsense --imu --max-frames 300 # Limited frames
python3 run_slam.py --realsense --imu --record data/bags/room_loop.bag
```
- **Hardware:** Intel RealSense D435i depth+RGB camera
- **Expected specs:** 
  - 640×480 RGB + depth @ 30 FPS
  - Baseline: 0.0499m
  - Calibrated intrinsics: fx=606.75, fy=606.57, cx=320.19, cy=237.06

#### **Bag Replay (Recorded Data)**
```bash
python3 run_bag.py data/bags/room_loop.bag            # Replay recorded bag
python3 run_bag.py data/bags/room_loop.bag --max-frames 200
```
- **Hardware:** None needed for replay
- **Prerequisite:** `.bag` file(s) from a prior hardware session
- **Format:** ROS rosbag format with camera intrinsics metadata

## Output & Artifacts

Every run creates a timestamped directory: `runs/run_<TIMESTAMP>/`

### **Files Generated (Per Run)**
- `config.json` — Exact hyperparameters used
- `telemetry.json` — Per-frame timing, status codes, tracking confidence
- `summary.json` — Aggregate stats: frame count, keyframes, loop closures, ATE (if ground truth available)
- `map.ply` — 3D point cloud (text-format PLY, viewable in MeshLab/CloudCompare/any 3D viewer)

### **Bundling Runs for Sharing**
```bash
python3 -m pyslam.tools.bundle runs/run_1234567890
```
Zips the entire run directory for easy sharing/archival.

## Known Limitations (Phase 0)

| Limitation | Impact | Mitigation |
|-----------|--------|-----------|
| **Single-threaded** | ~300ms/frame (offline) on reference hardware | Use Phase 1+ for vectorization |
| **No real-time** | Not suitable for live robotics yet | Synthetic/batch testing OK |
| **Corridor loops don't close** | Retrieval weak over long time gaps | Stick to tight square-loop scenarios |
| **No IMU fusion** | IMU recorded but not used in odometry | Phase 5 upgrade planned |
| **No threading** | Single Python thread | By design; intentional for Phase 0 |
| **No LTM (Long-Term Memory)** | Working memory unbounded | Phase 2+ upgrade |

## Step-by-Step Setup for Ubuntu

### **1. Install Python & Pip**
```bash

sudo apt install python3 python3-pip python3-dev
```


```bash

```

Expected: `6/6 passed` in ~50 seconds

```bash

# Or harder scenario:
python3 run_synth.py --scenario corridor
```

## Potential Issues & Troubleshooting

### **Issue 1: ImportError for GTSAM**
```
ModuleNotFoundError: No module named 'gtsam'
```
**Solution:** This is OK! Pipeline automatically uses native backend. No action needed.

### **Issue 2: OpenCV ImportError**
```
ImportError: libGL.so.1 not found
```
**Solution:**
```bash
sudo apt install libgl1-mesa-glx libglib2.0-0
```

### **Issue 3: Selftest Fails**
```
[FAIL] test_name: assertion error
```
**Action:** Do NOT proceed to hardware. Debug with:
```bash
python3 -m pyslam.tools.env_probe
```

### **Issue 4: No RealSense Camera Found**
```
RuntimeError: librealsense.so not found
```
**Solution:** Install without camera support (synthetic/bag testing only):
```bash
# Skip: pip install pyrealsense2
# Just install the rest and use --scenario flags
```

### **Issue 5: Numpy Version Conflict**
```
ERROR: numpy>=2.0 AND numpy<2.0
```
**Solution:** Use Python 3.9+ or install numpy 1.x explicitly:
```bash
pip install 'numpy<2.0' gtsam
```

## Recommendations

### **For Offline Development/Testing**
✅ **Fully viable.** Use synthetic scenarios and bag replay exclusively.

### **For Real-time Robotics**
⚠️ **Not yet.** Phase 0 is single-threaded and ~300ms/frame. Suitable for evaluation only. Phase 1+ will add parallelization.
